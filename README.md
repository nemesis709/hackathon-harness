# 경량 AI 개발 하네스

시간 제한이 있는 실무형 AI 협업 과제(약 4시간)를 위한 최소 하네스다. AI 코딩 에이전트가 요구사항을 확인한 뒤 구현하고, 실행 근거로 완료를 판단하고, 사용자가 결과물을 스스로 설명할 수 있게 돕는다.

> **사용 전 확인**: 시험·대회에서 개인 하네스나 사전 작성한 프롬프트를 반입할 수 있는지는 규정마다 다르다. 규정을 확인하기 전에는 로컬 연습용으로만 쓴다.

## 구성

```text
AGENTS.md                          모든 작업에 적용하는 원칙 8개와 단계 안내
skills/
  requirement-discovery/SKILL.md   담당자 질문 흐름 (답에 따라 다음 질문을 고른다)
  implementation-planning/SKILL.md 기능 단위 분해, 순서, 과설계 차단, 승인 필요 판단
  verification-review/SKILL.md     실행 검증 루프, 3관점 리뷰, 오류 원인 찾기, 완료 판정
  explainability/SKILL.md          근거 기반 설명 정리, 이해도 점검 질문
templates/
  requirements.md                  요구사항·규칙·검증 케이스
  decisions.md                     남길 가치가 있는 결정만
  verification.md                  실행 기록·케이스 결과·리뷰 지적·미구현
                                   (설정 때 프로젝트의 notes/ 로 복사한다)
```

평가 관점과의 대응:

| 관점 | 주로 돕는 파일 |
|---|---|
| 문제 정의·요구사항 발견·범위 관리 | `requirement-discovery`, `implementation-planning` |
| 동작하는 결과물·검증·오류 수정 | `verification-review` |
| 설계 의도·구현 원리·한계 설명 | `explainability`, `notes/decisions.md` |

## 설정 (2~3분)

외부 도구, MCP 서버, 스크립트, 네트워크가 필요 없다. 마크다운 파일만 복사한다.

`<…>` 는 실제 경로로 바꿔 넣는다.

```bash
H=<이 폴더 경로>; P=<과제 프로젝트 경로>
cp "$H/AGENTS.md" "$P/"            # 이미 AGENTS.md 가 있으면 덮어쓰지 말고 내용을 뒤에 붙인다
cp -R "$H/skills" "$P/"
mkdir -p "$P/notes" && cp "$H"/templates/*.md "$P/notes/"   # 템플릿은 notes/ 에 바로 채워 쓴다
```

에이전트별 진입점:

| 에이전트 | 추가 작업 |
|---|---|
| `AGENTS.md` 를 읽는 도구 (Codex CLI 등) | 없음 |
| Claude Code | 프로젝트 루트에 `CLAUDE.md` 를 만들고 `@AGENTS.md` 한 줄을 넣는다. 이미 있으면 그 줄만 추가한다 |
| 진입 파일을 자동으로 읽지 않는 도구 | 첫 메시지에 "`AGENTS.md` 를 읽고 따르라"고 쓴다 |

스킬 자동 등록은 필요 없다. `AGENTS.md` 의 단계 표가 각 `SKILL.md` 경로를 가리키므로, 에이전트는 해당 단계에서 그 파일을 일반 문서로 읽는다. 쓰는 도구가 `SKILL.md` 자동 인식을 지원하면 그 도구의 스킬 폴더에 `skills/` 를 추가로 복사해도 된다.

## 사용 흐름

1. 과제를 받으면 "요구사항 발견부터 하자"고 지시한다. AI 가 질문을 제안하면 사용자가 담당자에게 묻고 답을 그대로 붙여 넣는다.
2. Must 와 검증 케이스가 정해지면 "구현 계획을 세워라"고 지시한다. 승인 필요 항목에 답한다.
3. 기능 하나를 구현할 때마다 "검증해라"고 지시한다. 완료 보고에 실행 근거가 없으면 받아들이지 않는다.
4. 마지막 30분에는 새 기능을 시작하지 않는다. 제출 직전 검증을 한 번 돌리고 "설명을 정리하고 나를 점검해라"고 지시한다.

## 제출 전 정리

- 과제 규정이 하네스 파일 제출을 원하지 않으면 `AGENTS.md`·`CLAUDE.md`·`skills/` 를 지운다.
- `notes/` 는 작업 과정의 근거이므로 제출물에 포함할지 규정에 따라 정한다.

## 한계

- 규칙은 문장으로만 강제된다. 에이전트가 따르지 않을 수 있으므로 사용자가 완료 보고의 근거를 직접 확인해야 한다.
- 특정 언어·프레임워크용 규칙은 넣지 않았다. 과제가 제공한 스택의 관례를 따른다.
- 별도 컨텍스트 리뷰어(서브에이전트)는 선택 사항이며, 지원하지 않는 도구에서는 같은 세션의 3관점 리뷰만 한다.
